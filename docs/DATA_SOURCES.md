# 每日盤前分析 V1.0 — 資料來源規格

**文件狀態：定案版**  
**時區：Asia/Taipei**

## 1. 資料來源優先級

所有資料依下列順序取得：

1. 官方 Open API
2. 已驗證官方 Proxy
3. 備援 API／Proxy
4. 主要網站資料擷取
5. 備援網站資料擷取
6. 最近一次有效資料
7. `missing`

只有在較高優先級來源無法取得、格式錯誤、日期不符、資料過期或驗證失敗時，才可使用下一層來源。每次跳級都必須記錄原因。

## 2. 主要資料來源

### 2.1 TAIFEX

用途：台指期行情、三大法人未平倉量、選擇權鏈、法人部位、關鍵價位、Gamma、Call Wall、Put Wall、Gamma Flip、Max Pain，以及歷史比較。

主要 Proxy：

`https://taifex.grichtoyang.workers.dev/`

使用前必須確認 HTTP 回應、格式、資料日期、必要欄位、數值單位及非空內容。

### 2.2 TWSE／TAIEX

用途：加權指數、成交量、三大法人買賣超、融資融券、借券及現貨市場資料。

優先使用官方資料或已驗證 Proxy；失敗時依固定 Fallback 順序處理並記錄。

### 2.3 全球市場

可包含 S&P 500、Nasdaq、Dow Jones、SOX、美債 2Y／10Y／20Y／30Y、美元指數、USD/TWD、USD/JPY、Nikkei、韓國主要指數及 BTC。

每項資料必須記錄市場日期、資料時間、來源、是否延遲及資料狀態。

### 2.4 財經與產業新聞

新聞至少記錄標題、來源、發布時間、事件摘要、可能影響及影響判斷的限制；不得只列標題。

## 3. 來源角色與資料狀態

來源角色：

- `primary`：主要來源
- `fallback`：替代來源
- `last_valid`：最近一次有效資料

資料狀態：

- `fresh`
- `delayed`
- `stale`
- `missing`
- `invalid`
- `partial`
- `estimated`
- `fallback`
- `insufficient_data`

`fallback` 是資料來源切換後的明確狀態；`stale` 表示資料過期。兩者可同時成立，並須保留原始資料日期。

## 4. 資料驗證

每次取得資料後，必須檢查：

1. HTTP 狀態
2. 預期回應格式
3. JSON／CSV／文字是否可解析
4. 必要欄位
5. 是否為空
6. 資料日期
7. 資料時間
8. 數值有效性
9. 單位與欄位意義
10. 延遲、過期或部分資料狀態

驗證失敗時不得直接進入分析，必須記錄錯誤並啟用下一層來源。

## 5. 原始資料保存

原始資料不可覆寫。每筆原始資料至少保存：

- `source`
- `source_role`
- `endpoint`
- `request_time`
- `response_time`
- `http_status`
- `raw_payload`
- `data_date`
- `data_timestamp`
- `data_status`
- `error_code`
- `validation_errors`

正規化資料及分析結果須另行保存。

## 6. 歷史比較

比較前次資料時，必須確認比較日期、時間、資料定義、單位、來源及缺值狀況一致。無法建立有效比較時，標示 `insufficient_data`，不得自行推算。

## 7. 選擇權資料規則

資料必須區分近月、當週、到期月份、Call／Put、外資、造市商、OI、成交量、價格及 Gamma 資料。

Call Wall、Put Wall、Gamma Wall、Gamma Flip、Max Pain 只是市場結構參考，不能單獨產生交易訊號，必須結合價格行為、成交量、未平倉量及市場狀態。

## 8. 來源失敗處理

來源失敗時必須：

1. 記錄錯誤。
2. 記錄失敗來源及原因。
3. 依固定 Fallback 順序繼續。
4. 標示資料狀態。
5. 將影響傳遞至分析、報告及 Dashboard。
6. 不得因單一來源失敗而停止整體流程。

## 9. 資料誠信與禁止事項

不得：

- 虛構來源或資料。
- 將缺失資料補成 `0`。
- 將估算值當實際值。
- 將推測當事實。
- 將延遲資料標示為即時。
- 隱藏來源切換或 Fallback。
- 省略資料日期與時間。
- 以單一選擇權價位判定必然漲跌。
- 使用未驗證資料作為確定結論。

## 10. 最低交付要求

資料層至少提供：

- 原始資料或失敗紀錄
- 正規化資料
- 資料驗證結果
- 來源狀態
- Fallback 狀態
- 資料品質總覽
- 缺失欄位
- 錯誤清單
- 可供分析模組使用的結構化資料

資料不足時仍須產出部分結果，並明確標示限制。
