# 每日盤前分析 V1.0 — 資料來源規格

**文件狀態：定案版**  
**時區：Asia/Taipei**

## 1. 資料來源優先級

所有資料依下列順序取得：

1. 官方 Open API
2. 已驗證官方 Proxy
3. 備援 API／Proxy
4. 主要網站資料擷取
5. 備援網站資料擷取
6. 最近一次有效資料
7. `missing`

不得跳過較高優先級來源而直接使用較低優先級來源，除非前者無法取得、格式錯誤、日期不符、資料過期或驗證失敗。

## 2. 主要資料來源

### 2.1 TAIFEX

用途：

- 台指期行情
- 台指期三大法人未平倉量
- 選擇權鏈
- 選擇權法人部位
- 選擇權關鍵價位
- Gamma、Call Wall、Put Wall、Gamma Flip、Max Pain
- 期貨與選擇權歷史比較

主要 Proxy：

`https://taifex.grichtoyang.workers.dev/`

使用前必須確認：

- HTTP 回應正常
- 回應格式可解析
- 資料日期正確
- 必要欄位存在
- 數值單位正確
- 非空資料

### 2.2 TWSE／TAIEX

用途：

- 加權指數
- 成交量
- 三大法人買賣超
- 融資融券
- 借券
- 現貨市場相關資料

來源優先使用官方資料或已驗證 Proxy。若官方來源失敗，必須依 Fallback 順序處理並記錄。

### 2.3 全球市場

可包含：

- S&P 500
- Nasdaq
- Dow Jones
- SOX
- 美債殖利率：2Y、10Y、20Y、30Y
- 美元指數
- USD/TWD
- USD/JPY
- Nikkei
- 韓國主要指數
- BTC

每項資料必須記錄市場日期、收盤時間或資料時間、來源及是否延遲。

### 2.4 財經與產業新聞

用途：

- 重大總體經濟事件
- Fed／利率／通膨
- AI 與半導體產業
- 企業財報
- 影響台股或台指期的重大事件

新聞不得只列標題，至少應記錄：

- 標題
- 來源
- 發布時間
- 事件摘要
- 可能影響
- 影響方向的限制

## 3. 來源角色

每筆資料必須標示：

- `primary`：主要來源
- `fallback`：替代來源
- `last_valid`：最近一次有效資料

不得把 `fallback` 或 `last_valid` 資料標示為正常即時資料。

## 4. 資料驗證

每次取得資料後，必須檢查：

1. HTTP 狀態
2. 回應是否為預期格式
3. JSON／CSV／文字是否可解析
4. 必要欄位是否存在
5. 資料是否為空
6. 資料日期是否符合執行日期
7. 資料時間是否合理
8. 數值是否為有效數字
9. 單位與欄位意義是否正確
10. 是否為延遲、過期或部分資料

驗證失敗時不得直接進入分析，必須標記資料狀態並啟用下一層來源。

## 5. 資料狀態

允許狀態：

- `fresh`
- `delayed`
- `stale`
- `missing`
- `invalid`
- `partial`
- `estimated`
- `insufficient_data`

規則：

- `missing` 不得轉換為零。
- `estimated` 必須明確標示估算。
- `delayed` 不得標示為即時。
- `stale` 必須記錄原始資料日期。
- `partial` 必須列出缺少的欄位。
- `invalid` 不得作為未經說明的分析依據。

## 6. 原始資料保存

原始資料不可被覆寫。每筆原始資料至少保存：

- `source`
- `source_role`
- `endpoint`
- `request_time`
- `response_time`
- `http_status`
- `raw_payload`
- `data_date`
- `data_timestamp`
- `data_status`
- `error_code`

正規化資料及分析結果應另行保存，不得取代原始資料。

## 7. 歷史比較

需要比較前次資料時，必須確認：

- 比較基準日期
- 比較基準時間
- 資料定義一致
- 單位一致
- 來源可追溯
- 是否存在缺值或資料延遲

若無法建立有效比較，必須標示 `insufficient_data`，不得自行推算。

## 8. 選擇權資料特別規則

選擇權資料必須區分：

- 近月
- 當週
- 到期月份
- Call／Put
- 外資
- 造市商
- OI
- 成交量
- 價格
- Gamma 相關資料

Call Wall、Put Wall、Gamma Wall、Gamma Flip、Max Pain 僅是市場結構參考，不能單獨直接產生交易訊號，必須結合價格行為、成交量、未平倉量及市場狀態。

## 9. 來源失敗處理

來源失敗時必須：

1. 記錄錯誤。
2. 記錄失敗來源。
3. 記錄失敗原因。
4. 依固定 Fallback 順序繼續。
5. 標示資料狀態。
6. 將影響傳遞至分析、報告及 Dashboard。
7. 不得因單一來源失敗而停止整體流程。

## 10. 禁止事項

不得：

- 虛構來源或資料。
- 把缺失資料補成 `0`。
- 把估算值當實際值。
- 把延遲資料當即時資料。
- 使用未驗證的資料作為確定結論。
- 隱藏來源切換或 Fallback。
- 省略資料日期與時間。
- 以單一選擇權價位判定必然漲跌。

## 11. 最低交付要求

每次執行後，資料層至少應提供：

- 原始資料或失敗紀錄
- 正規化資料
- 資料驗證結果
- 來源狀態
- Fallback 狀態
- 資料品質總覽
- 缺失欄位
- 錯誤清單
- 可供分析模組使用的結構化資料

資料不足時，仍須產出部分結果並明確標示限制。
