## 報告輸出硬性規則

1. 不得虛構資料。
2. 缺失資料不得補成 `0`。
3. 不得將估算值當作實際值。
4. 不得將延遲資料標示為即時資料。
5. 每個重要數據都必須標示資料日期、時間、來源及狀態。
6. 每個分析模組都必須有結論、信心及限制。
7. 資料不足時，必須降低分析信心並明確說明。
8. 發生錯誤後不得只輸出錯誤訊息而停止。
9. 即使部分模組失敗，也必須盡可能產出 Markdown 報告及 Dashboard JSON 或 partial JSON。
10. 交易情境必須包含觸發條件、確認條件、失效條件及風險控管。
11. 選擇權關鍵位只能作為分析依據之一，不得單獨視為交易訊號。
12. Markdown 報告與 Dashboard JSON 的結論必須一致。
13. 最終狀態只能使用本文件定義的狀態名稱。
14. 「報告已產出但流程仍有錯誤」應記錄於錯誤、未完成項目及最終說明，不另設獨立狀態。
