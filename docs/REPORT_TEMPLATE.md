# 每日盤前分析 V1.0 — Markdown 報告模板

> **文件狀態：V1.0 正式定案版**  
> 本文件直接覆寫既有 `docs/REPORT_TEMPLATE.md`，不升版、不另建 V1.1。  
> 報告固定包含五大模組：現貨、重要市場、期貨、選擇權、綜合總結。

## 0. 執行與資料品質規則

1. 不得因單一 API、資料源或模組錯誤而提前停止。
2. 即使資料不完整，也必須產出完整 Markdown 報告，並依實際狀況標註 `OK`、`Fallback`、`Partial`、`Unavailable`、`Not Computable` 或 `Stale`。不得以估算值、前一日數值或零值填補缺漏資料。
3. 不得捏造數據；所有數值須附資料日期、來源與計算說明。
4. 第五模組只整合前四模組結果，不重新抓取相同資料。
5. 必須區分「日盤後 OI 存量」與「夜盤新增交易流量」，不得混用。
6. 若不同資料來源的交易日期、盤別或時間戳不同，必須明確揭露，不得直接視為同一交易日資料，也不得在未說明的情況下混合計算或下結論。
7. 報告最後必須列出成功項目、失敗項目、Fallback 狀態與整體完成度。
8. 整體完成度＝已成功取得並完成分析的必要項目數 ÷ 必要項目總數 × 100%。`Fallback` 視為已完成但須揭露備援來源；`Partial` 依實際完成比例計算；`Unavailable` 與 `Not Computable` 不計入已完成項目。

## 4.2 日盤與夜盤資料規則

- 選擇權 OI 以日盤結束後公布資料為準。
- 除非資料來源明確提供並可驗證，否則不得假設選擇權存在可直接取得的夜盤獨立即時 OI。若未取得可驗證資料，必須標註 `Unavailable` 或 `Not Computable`。
- 夜盤新增資訊以三大法人 Call／Put 交易口數與交易金額為主。
- 夜盤 Call／Put 交易流量不得直接等同夜盤新增 OI。
- 夜盤資訊應專注於新增法人交易，避免重複既有盤前 OI 分析。

## 4.3 選擇權部位：夜盤 Buy/Sell Call／Put 交易金額

### 必須觀察的重點

1. 外資 Buy Call 金額是否增加，是否代表偏多交易需求上升。
2. 外資 Sell Call 金額是否增加，是否代表上方壓力、收益型策略或其他組合策略。
3. 外資 Buy Put 金額是否較前一日異常暴增，是否可能反映避險需求升高。
4. 外資 Sell Put 金額是否增加，是否可能反映下方承接或收取權利金策略；不得單獨視為絕對看多。
5. 自營商 Buy/Sell Call／Put 是否與外資同向或分歧。
6. 交易金額變化是否伴隨夜盤價格變化，以及是否與期貨法人流向一致。
7. 單一 Buy/Sell 類別不得直接等同完整策略，須搭配履約價、到期月份、成交量、OI 與其他部位判讀。

### 外資 Buy Put 異常暴增判定

- 比較當日與前一交易日 Buy Put 金額。
- 若資料足夠，另比較近 5 個交易日平均值。
- 標註：正常／明顯增加／異常暴增／資料不足。
- 若 Buy Put 異常暴增，必須在結論中揭露：
  - 可能是避險需求增加
  - 可能反映下行風險升高
  - 不可單獨視為看空方向，仍須搭配期貨、現貨、履約價與 OI 判斷
