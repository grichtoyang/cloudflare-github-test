# 每日盤前分析 V1.0 — Dashboard Specification

> **文件名稱：** `DASHBOARD_SPEC.md`  
> **文件狀態：** V1.0 正式定案候選版  
> **適用專案：** 每日盤前分析 V1.0  
> **用途：** 定義每日盤前分析 Dashboard 的資料、版面、狀態、顏色、更新與錯誤處理規則。  
> **重要規則：** 本文件只定義 Dashboard 顯示與判讀規格，不負責重新抓取資料，也不取代 `REPORT_TEMPLATE.md`。

---

## 0. 核心定位

Dashboard 是「每日盤前分析」的必要核心介面，不是附加功能。

Dashboard 必須讓使用者確認：

1. 今日資料是否成功取得。
2. 台股、台指期與選擇權的主要方向。
3. 重要關鍵價位。
4. 法人籌碼是否支持價格方向。
5. 哪些資料不可用、原因及是否使用 Fallback。
6. 今日交易應偏向順勢、區間、等待確認或避免交易。

不得捏造數據，也不得用估算值、前一日數值或零值填補缺漏。

## 1. 資料與責任邊界

Dashboard 只能使用資料收集、Fallback、日期對齊、分析引擎產出的結構化結果，不得自行重新抓取相同 API 或重複計算報告模組資料。

固定流程：

```text
資料來源 → 資料收集／Fallback → 資料驗證與日期對齊 → 分析引擎 → 結構化結果 → Dashboard
```

所有資料卡片與指標均須支援：

- `OK`：成功取得且可使用。
- `Fallback`：主要來源失敗，使用可驗證備援來源。
- `Partial`：只有部分欄位或期間可用。
- `Unavailable`：資料未取得。
- `Not Computable`：資料存在，但不足以合法計算。
- `Stale`：資料過期或與目前交易時段不一致。

## 2. Dashboard 版面總覽

固定八個區塊，順序不得任意調換：

1. 系統狀態列
2. 市場總覽
3. 台股現貨
4. 台指期
5. 選擇權籌碼與關鍵位
6. 夜盤法人流向
7. 綜合方向與交易情境
8. 資料品質與完成度

方向、價格與選擇權關鍵位必須位於上方首屏。

## 3. 系統狀態列

必須顯示：

- 分析日期
- 報告產出時間
- 各資料源最後更新時間
- TAIFEX、TWSE 及其他來源狀態
- Fallback 狀態
- 整體完成度
- 報告狀態：完成／部分完成／資料不足

若交易日期、盤別、時間戳或結算日期不一致，必須明確揭露，不得視為同一時間點資料。

## 4. 市場總覽

至少顯示：

- 台股加權指數
- 台指期近月
- 期現貨基差
- 夜盤最新價或收盤
- NASDAQ、S&P 500、SOX、道瓊、VIX
- DXY、美國 10 年期公債殖利率
- 日經、韓國指數

每項至少顯示數值、漲跌點、漲跌幅、資料日期／時間與資料狀態。

市場方向只可顯示：`偏多`、`偏空`、`中性`、`分歧`、`資料不足`，且須由分析結果支持。

## 5. 台股現貨

### 5.1 行情

必須顯示加權指數、開高低收、漲跌點／幅、成交量、成交金額、上漲家數、下跌家數、平盤家數。

### 5.2 技術結構

必須顯示 5／10／20 日均線、RSI、ATR、日線結構、支撐位與壓力位。

日線結構只可使用：`多頭`、`空頭`、`震盪`、`Transition`、`資料不足`。

### 5.3 現貨法人

必須顯示外資、投信、自營商及三大法人合計的買賣超、連續性與判讀，並顯示融資餘額、融券餘額、融資維持率、借券餘額及借券賣出。

## 6. 台指期

### 6.1 期貨行情

必須顯示近月合約、收盤／最新價、開高低收、漲跌點／幅、成交量、OI、OI 增減、期現貨基差、資料日期與盤別。

### 6.2 日盤後法人未平倉

必須顯示外資及陸資、投信、自營商、三大法人合計的多單、空單、淨未平倉、較前日變化與判讀。

### 6.3 方向判讀

必須顯示外資淨部位方向、三大法人合計方向、法人與價格是否一致或背離，以及 `偏多／偏空／中性／分歧／資料不足`。

## 7. 選擇權籌碼與關鍵位

此區塊為 Dashboard 必要核心。

### 7.1 合約範圍

必須清楚區分近月、當週、Call、Put、到期月份、資料日期及日盤／夜盤資訊。不同到期月份不得混為同一組關鍵位。

### 7.2 必須顯示的關鍵位

至少包含：

- Call Wall
- Put Wall
- Gamma Wall
- Gamma Flip
- Max Pain
- 上方主要壓力
- 下方主要支撐

每一個關鍵位必須顯示名稱、履約價／點位、合約範圍、資料日期、來源、狀態、與前次資料變化及判讀說明。

### 7.3 法人部位

必須顯示外資 Call／Put、自營商 Call／Put、Call／Put OI、OI 增減、主要履約價集中區及法人偏多／偏空／避險／分歧。

造市商資料只有在來源實際提供且可驗證時才顯示。

### 7.4 夜盤選擇權規則

- OI 以可驗證的日盤結束後資料為準。
- 不得假設存在可直接取得的夜盤獨立即時 OI。
- 夜盤 Buy Call／Sell Call／Buy Put／Sell Put 金額，只有資料源明確提供且可驗證時才顯示。
- 沒有可驗證分類金額時顯示 `Unavailable`。
- 不得用成交量、總交易金額或其他指標替代分類金額。
- 夜盤交易流量不得直接等同新增 OI。

### 7.5 關鍵位語意

- Call Wall：壓力區
- Put Wall：支撐區
- Gamma Wall：重要反應區
- Gamma Flip：轉換／警戒區
- Max Pain：中性參考位
- 資料不足：灰色或中性狀態

實際顏色由前端主題統一管理，但語意必須固定。

## 8. 夜盤法人流向

必須分開顯示：

### A. 日盤後法人未平倉基準

這是部位存量，標示為：`日盤後 OI 基準`。

### B. 夜盤新增交易流量

這是交易流量，標示為：`夜盤新增交易流量`。

兩者不得合併成同一指標。

夜盤法人表必須顯示外資及陸資、投信、自營商、三大法人合計的多單交易量、空單交易量、多空淨交易量、與日盤後基準關係及判讀。

夜盤價格卡必須顯示夜盤漲跌點／幅、夜盤收盤／最新價、成交量、相對日盤收盤、夜盤方向，以及價格與法人流向的 `一致／背離／分歧／資料不足`。

## 9. 綜合方向與交易情境

### 9.1 市場狀態

只可顯示：`Trend`、`Range`、`Transition`、`TBD`。

`TBD` 表示資料或條件不足，不得強行判定方向。

### 9.2 四層判讀

依序顯示：

1. Regime Engine
2. Options Map
3. Opening Range
4. Price Action

每層至少顯示狀態、判讀、是否通過及資料狀態。

### 9.3 綜合方向

只可顯示：`偏多`、`偏空`、`中性`、`分歧`、`等待確認`、`TBD`。

### 9.4 交易情境

可顯示順勢做多、順勢做空、回調交易、突破交易、盤整區間、等待確認、避免交易，但不得直接視為下單指令。

每個情境須附觸發條件、失效條件、主要風險、參考支撐／壓力及資料充分性。

## 10. 資料品質與完成度

必須顯示：必要項目總數、已完成項目數、OK、Fallback、Partial、Unavailable、Not Computable、Stale 項目數及整體完成度。

公式：

```text
整體完成度
= 已成功取得並完成分析的必要項目數
  ÷ 必要項目總數 × 100%
```

規則：

- `OK`：計入已完成。
- `Fallback`：計入已完成，但須揭露備援來源。
- `Partial`：依實際完成比例計算。
- `Unavailable`：不計入已完成。
- `Not Computable`：不計入已完成。
- `Stale`：依是否仍可合法使用判定，並明確揭露。

必須列出成功項目、失敗項目、Fallback 項目、無法計算項目、資料過期項目及其對結論的影響。

## 11. 顯示與互動規則

每張卡片至少包含：標題、主要數值或狀態、資料日期／時間、資料來源、狀態標籤及簡短判讀。

缺漏資料不得顯示為 `0`、沒有說明的 `-`、前一日數值、估算值或假設值。應顯示 `Unavailable` 或 `Not Computable` 並說明原因。

Dashboard 更新時必須保留日期與時間，不得混合新舊資料而不標示；單一模組失敗不得使整份 Dashboard 停止。

手機版必須垂直排列，選擇權關鍵位不得隱藏，必要數值不得截斷；表格可水平滑動但不得刪除必要欄位。

## 12. 禁止事項

1. 捏造任何數據。
2. 用前一日數值填補缺漏。
3. 用零值表示未知。
4. 用估算值冒充實際值。
5. 混用日盤後 OI 與夜盤交易流量。
6. 把夜盤交易量稱為夜盤即時 OI。
7. 無可驗證資料時顯示造市商部位。
8. 無可驗證分類金額時顯示 Buy/Sell Call／Put 金額。
9. 混合不同日期、盤別或時間戳資料。
10. 因單一 API 失敗而停止整份 Dashboard。
11. 將 `TBD` 強制轉換成偏多或偏空。
12. 將分析情境表述為保證獲利或下單指令。
