# 每日盤前分析 V1.0 — Dashboard Specification

> **文件狀態：V1.0 正式定案候選版**  
> **文件用途：** 定義 Dashboard 的展示責任、頁面架構、資料契約、狀態規則、圖表要求與驗收標準。  
> **制定依據：**  
> 1. `dashboard的架構討論.md`  
> 2. `REPORT_TEMPLATE.md`

---

## 0. 文件定位與適用範圍

Dashboard 是「每日盤前分析 V1.0」的**視覺化展示層**，不是獨立分析引擎。

### 0.1 核心原則

1. ChatGPT／分析流程負責資料整合、分析、判讀與結論。
2. Dashboard 只展示結構化分析結果，不自行改寫、推導或覆蓋分析結論。
3. Markdown 報告與 Dashboard JSON 必須來自同一份分析結果。
4. Dashboard 不直接解析 Markdown。
5. 所有頁面共用同一份 `dashboard_latest.json`。
6. 切換頁面不得重新抓資料。
7. 切換頁面不得重新計算結論。
8. 必須揭露資料品質、延遲、缺失、Fallback、錯誤與未完成項目。
9. 單一資料源、模組或圖表失敗，不得使整個 Dashboard 崩潰。
10. 資料不足時不得強行產生方向判斷。

## 2. Page Selection

Page Selection 是 V1.0 的**必要核心功能**，不是選配。

### 2.1 固定五頁

| Page ID | 頁面名稱 | 主要內容 |
|---|---|---|
| `spot` | 現貨 | 台股指數、法人、融資融券、借券、技術結構 |
| `global_markets` | 重要市場 | 美股、SOX、美債、美元、匯率、亞洲、Bitcoin、新聞 |
| `futures` | 期貨 | 台指期、日盤、夜盤、期現價差、法人 OI、夜盤流向 |
| `options` | 選擇權 | 近月／當週、Call Wall、Put Wall、Gamma Wall、Gamma Flip、Max Pain、OI、GEX |
| `summary` | 總結 | 綜合方向、Regime、燈號、支撐壓力、情境、風險 |

### 2.2 行為要求

- 預設開啟 `summary`。
- 五頁皆可切換。
- 目前頁面必須高亮。
- 目前頁面必須具備無障礙標記，例如 `aria-selected`。
- 桌面使用響應式頁籤。
- 手機支援橫向滑動頁籤或下拉選單。
- 切換頁面不得重新抓取資料。
- 切換頁面不得重新計算分析結論。
- 不得造成整頁水平溢出。
- 必須支援鍵盤操作。
- 頁面切換失敗時，仍須保留已載入資料與錯誤提示。

## 3. 共通顯示標準

### 3.1 每個頁面必須顯示

- 報告日期。
- 產出時間。
- 時區：`Asia/Taipei`。
- 執行狀態。
- 資料品質。
- 分析信心。
- 資料延遲提示。
- Fallback 提示。
- 來源與更新時間。
- 未完成項目或錯誤提示（如有）。

### 3.2 每張數據卡至少顯示

1. 名稱。
2. 最新值。
3. 單位。
4. 漲跌／變化。
5. 前值（如有）。
6. 資料日期／時間。
7. 來源。
8. 狀態。

### 3.3 狀態值

可使用下列狀態：

- `OK`
- `Fallback`
- `Partial`
- `Unavailable`
- `Not Computable`
- `Stale`
- `missing`
- `invalid`
- `delayed`
- `estimated`

實作時應統一顯示文字與內部狀態，避免同一狀態有多種不一致寫法。

### 3.4 資料揭露規則

- 缺失資料不得補成 `0`。
- 沒有前值不得製造變化。
- 沒有單位不得自行猜測。
- 延遲資料不得標示為即時。
- 估算資料必須標示 `estimated` 與計算版本。
- Fallback 必須標示來源與使用原因。
- 不同交易日期、盤別或時間戳不得未經說明而混合。
- 任何數值均應能追溯至來源、資料時間與計算方式。

## 6. 期貨頁 `futures`

### 6.1 台指期日盤行情

- 近月台指期。
- 開盤／最高／最低／收盤。
- 最新價。
- 漲跌點／漲跌幅。
- 成交量（若取得）。
- 未平倉量 OI（若取得）。
- OI 增減（若取得）。
- 期現貨基差。
- 前高／前低。
- 日盤區間。

### 6.2 日盤後法人未平倉

必須展示：

- 外資及陸資多單未平倉。
- 外資及陸資空單未平倉。
- 外資及陸資淨未平倉。
- 投信淨未平倉。
- 自營商淨未平倉。
- 三大法人合計淨未平倉。
- 較前日變化。
- 資料日期與公布時間。
- 趨勢判斷。

外資期貨部位為主要觀察核心，投信與自營商為輔助。

### 6.3 夜盤展示

夜盤只保留三個核心：

#### A. 日盤後法人未平倉基準

- 外資及陸資淨未平倉。
- 投信淨未平倉。
- 自營商淨未平倉。
- 三大法人合計淨未平倉。
- 與前一交易日比較的增減。

#### B. 夜盤法人新增交易流向

- 夜盤法人交易口數／交易金額。
- 夜盤多單交易量。
- 夜盤空單交易量。
- 夜盤多空淨交易量。
- 外資、投信、自營商分項流向。
- 法人流向是否延續日盤後部位。
- 三大法人是否同向或分歧。

#### C. 夜盤價格與成交量

- 夜盤漲跌點。
- 夜盤漲跌幅。
- 夜盤收盤／最新價。
- 夜盤成交量。
- 夜盤高點／低點。
- 相對日盤收盤：高於／低於／接近。
- 夜盤方向：偏多／偏空／震盪。

### 6.4 嚴格限制

- 夜盤交易量／交易金額／多空淨交易量不得宣稱為盤中即時法人 OI。
- 日盤後法人未平倉是部位存量。
- 夜盤法人交易量是新增交易流量。
- 存量與流量不可混用。
- 只有取得可驗證的盤中法人 OI，才可使用「夜盤即時未平倉變化」。

### 6.5 期貨結論展示

必須展示：

- 期貨日盤後法人部位：偏多／偏空／中性／分歧／資料不足。
- 夜盤法人流向：偏多／偏空／分歧／資料不足。
- 夜盤價格與法人流向：一致／背離／無法判定。
- 對隔日日盤的方向與風險。
- 資料日期、盤別、公布時間與來源。

## 7. 選擇權頁 `options`

### 7.1 近月與當週必須分開

Dashboard 不得混淆：

- 近月選擇權。
- 當週選擇權。
- 到期月份。
- 履約價。
- 日盤後資料。
- 夜盤新增交易流量。

### 7.2 五大關鍵位

每個到期分類均應在資料可取得時展示：

- Call Wall。
- Put Wall。
- Gamma Wall。
- Gamma Flip。
- Max Pain。

每個關鍵位應揭露：

- 履約價。
- 到期月份。
- 資料日期／時間。
- 前值。
- 變化。
- 原始 OI／成交量（若適用）。
- 計算方式。
- 資料狀態。
- 是否為估算值。

### 7.3 其他必要資料

- Call OI。
- Put OI。
- Call／Put OI 差異。
- Call／Put 成交量。
- GEX。
- Gamma 分布。
- Delta（若取得）。
- Call／Put Ratio。
- 重要履約價。
- 外資部位。
- 自營商部位。
- 造市商部位：只有來源實際提供時才顯示。
- 與前次結算或前次資料的變化。

### 7.4 日盤與夜盤規則

- 選擇權 OI 以日盤結束後公布資料為準。
- 除非資料來源明確提供並可驗證，不得假設存在可直接取得的夜盤獨立即時 OI。
- 未取得可驗證資料時，標註 `Unavailable` 或 `Not Computable`。
- 夜盤新增資訊以法人 Call／Put 交易口數與交易金額為主。
- 夜盤 Call／Put 交易流量不得直接等同夜盤新增 OI。
- 夜盤資訊應專注於新增法人交易，避免重複既有盤前 OI 分析。

### 7.5 夜盤 Buy/Sell Call／Put 金額

若資料源實際提供，展示：

- Buy Call 金額。
- Sell Call 金額。
- Buy Put 金額。
- Sell Put 金額。
- 與前一交易日變化。
- 主要變化。
- 方向／風險判斷。

必須特別觀察：

- 外資 Buy Call 是否增加。
- 外資 Sell Call 是否增加。
- 外資 Buy Put 是否異常暴增。
- 外資 Sell Put 是否增加。
- 自營商與外資是否同向或分歧。
- 交易金額是否與夜盤價格及期貨法人流向一致。

### 7.6 外資 Buy Put 異常暴增

資料足夠時：

- 比較當日與前一交易日。
- 另比較近 5 個交易日平均值。
- 標註：正常／明顯增加／異常暴增／資料不足。

若異常暴增，Dashboard 必須顯示：

- 可能反映避險需求增加。
- 可能反映下行風險升高。
- 不可單獨視為絕對看空。
- 必須搭配期貨、現貨、履約價、OI 與其他部位判讀。

### 7.7 嚴格限制

- 造市商資料未提供時顯示 `missing`、`Unavailable` 或等效狀態，不得補 0。
- 估算 GEX 必須標示 `estimated` 與計算版本。
- 單一關鍵位不得直接當成交易訊號。
- 關鍵位必須搭配現貨、期貨、價格行為與 Market Regime。
- 不得將 Buy/Sell Call／Put 單一類別直接等同完整交易策略。
- 必須搭配履約價、到期月份、成交量、OI 與其他部位判讀。

## 8. 總結頁 `summary`

總結頁是預設首頁。

### 8.1 必要內容

- 綜合方向：
  - `bullish`
  - `bearish`
  - `neutral`
  - `insufficient_data`
- Market Regime：
  - `Trend`
  - `Range`
  - `Transition`
- 五大模組燈號。
- 主要支撐。
- 主要壓力。
- 上破情境。
- 下破情境。
- 震盪／等待情境。
- 交易偏向。
- 失效條件。
- 風險控管。
- 分析信心。
- 資料品質。
- 未完成項目。

### 8.2 總結頁不可省略的內容

總結頁不能只顯示「看多／看空」，還必須顯示：

- 結論依據。
- 關鍵數據。
- 期貨與選擇權一致性。
- 日盤後法人 OI。
- 夜盤法人新增流向。
- 夜盤價格與法人流向是否一致。
- 外資 Buy Put 風險狀態。
- 主要支撐與壓力。
- 失效條件。
- 主要交易風險。
- 分析信心。
- 資料限制。

### 8.3 情境展示

#### 情境 A：偏多

- 觸發條件。
- 支持證據。
- 目標／壓力。
- 失效條件。

#### 情境 B：偏空

- 觸發條件。
- 支持證據。
- 目標／支撐。
- 失效條件。

#### 情境 C：震盪／等待

- 觸發條件。
- 盤整區間。
- 不宜追價的原因。
- 轉強／轉弱確認條件。

## 9. 燈號規則

燈號由分析流程／分析引擎產出，前端只展示。

| 燈號 | 意義 |
|---|---|
| 綠燈 | 偏多／Bullish |
| 紅燈 | 偏空／Bearish |
| 黃燈 | 震盪／Transition／不明確 |
| 灰燈 | 資料不足／Insufficient data |

### 9.1 燈號要求

- 燈號必須附文字。
- 不得只靠顏色傳達意義。
- 真正中性與資料不足必須分開。
- 必須考慮色盲與無障礙。
- 燈號顏色不得覆蓋原始資料狀態。
- 若方向為 `neutral`，不可自動等同 `insufficient_data`。
- 若資料不足以判斷，應使用 `insufficient_data`／灰燈。

## 10. Dashboard JSON 資料契約

### 10.1 建議位置

```text
dashboard/data/dashboard_latest.json
```

### 10.2 基本結構

```json
{
  "meta": {
    "project": "每日盤前分析",
    "version": "V1.0",
    "report_date": "YYYY-MM-DD",
    "generated_at": "YYYY-MM-DDTHH:mm:ss+08:00",
    "timezone": "Asia/Taipei",
    "execution_status": "completed_with_warnings",
    "data_quality": "partial",
    "confidence": "medium",
    "default_page": "summary",
    "available_pages": [
      "spot",
      "global_markets",
      "futures",
      "options",
      "summary"
    ]
  },
  "key_data": {},
  "analysis": {},
  "charts": {},
  "errors": [],
  "fallbacks": [],
  "unfinished_items": []
}
```

### 10.3 欄位責任

| 欄位 | 責任 |
|---|---|
| `meta` | 報告日期、產出時間、時區、執行狀態、品質、信心、頁面設定 |
| `key_data` | 可直接展示的關鍵數據 |
| `analysis` | 模組結論、解讀、方向、情境與風險 |
| `charts` | 圖表所需的結構化資料 |
| `errors` | 錯誤紀錄 |
| `fallbacks` | Fallback 紀錄、來源與原因 |
| `unfinished_items` | 尚未完成、無法驗證或待補項目 |

### 10.4 JSON 必須遵守

- 不得以 `0` 代替缺失資料。
- 不得用前一日數值假裝最新值。
- 不得將估算值當成實測值。
- 每個重要數值應有日期／時間、來源與狀態。
- 圖表資料、數據卡與 Markdown 必須一致。
- JSON 即使資料不完整也必須產出最低限度結構。
- 若分析無法可靠判斷，應輸出 `insufficient_data`，不得強行輸出方向。

## 11. 圖表規則

### 11.1 原則

- 圖表只使用結構化分析結果。
- 圖表不得自行重新抓取資料。
- 圖表不得自行重新計算分析結論。
- 圖表與 Markdown、數據卡內容必須一致。

### 11.2 必要或優先圖表

1. 加權指數價格與成交量。
2. 現貨三大法人買賣超。
3. 融資融券變化。
4. 台指期價格、成交量與 OI。
5. 期貨三大法人淨未平倉。
6. 外資期貨淨部位趨勢。
7. 夜盤價格與成交量。
8. 夜盤法人多空交易流向。
9. 日盤後法人基準與夜盤新增流向對照。
10. 選擇權 Call／Put OI 分布。
11. 選擇權 Call／Put 成交量分布。
12. GEX 分布。
13. Call Wall／Put Wall／Gamma Wall／Gamma Flip／Max Pain。
14. Buy Call／Sell Call／Buy Put／Sell Put 金額變化。
15. 外資 Buy Put 金額與歷史平均比較（資料足夠時）。

### 11.3 圖表揭露

每張重要圖表應同時揭露：

- 圖表名稱。
- 資料日期與時間。
- 資料來源。
- 單位。
- 計算方式。
- 缺漏資料與限制。
- 是否使用估算值。
- 圖表對結論的影響。

資料不足時顯示「資料不足」，不得畫成零值或虛構線段。

## 12. 錯誤、Fallback 與不完整資料

### 12.1 錯誤處理

單一資料源、單一模組或單一圖表失敗時，必須：

- 保留其他成功資料。
- 顯示失敗資料源。
- 顯示受影響模組。
- 顯示錯誤原因。
- 顯示使用的 Fallback。
- 顯示對分析信心的影響。
- 列出未完成項目。

### 12.2 最低限度輸出

即使資料不完整，也必須產出 JSON，並顯示：

- `partial` 或其他適當狀態。
- 已取得資料。
- 錯誤。
- Fallback。
- 未完成項目。
- 是否影響最終方向判斷。

### 12.3 與 Markdown 報告一致

Dashboard 必須反映 `REPORT_TEMPLATE.md` 的執行規則：

- 不因單一錯誤提前停止。
- 必須完成整體報告流程。
- 必須揭露成功、失敗、Fallback、未驗證項目。
- 必須揭露整體完成度。
- `Fallback` 視為已完成但須揭露備援來源。
- `Partial` 依實際完成比例計算。
- `Unavailable` 與 `Not Computable` 不計入已完成項目。

## 13. 整體完成度與資料品質

### 13.1 完成度公式

```text
整體完成度
= 已成功取得並完成分析的必要項目數
÷ 必要項目總數
× 100%
```

規則：

- `OK`：視為完成。
- `Fallback`：視為完成，但必須揭露備援來源。
- `Partial`：依實際完成比例計算。
- `Unavailable`：不計入已完成項目。
- `Not Computable`：不計入已完成項目。
- `Stale`：須揭露資料過期風險，是否計入完成需依實際規則判定。
- 完成度不得只以 API 成功率代替，必須反映「取得資料並完成分析」的程度。

### 13.2 Dashboard 必須展示

- 整體資料品質。
- 整體完成度。
- 各模組狀態。
- 各資料源狀態。
- Fallback 使用情形。
- 重要缺失。
- 是否影響方向判斷。
- 分析信心。

## 14. RWD、無障礙與前端限制

### 14.1 RWD

- 桌面版可清楚展示五頁與數據卡。
- 手機版不得造成整頁水平溢出。
- 頁籤可橫向滑動或改用下拉選單。
- 卡片需可依螢幕寬度重排。
- 圖表需能在窄螢幕閱讀。
- 長文字、狀態與錯誤訊息不可被截斷。

### 14.2 無障礙

- Page Selection 必須支援鍵盤。
- 目前頁面使用 `aria-selected` 或等效標記。
- 燈號必須附文字。
- 顏色不得是唯一資訊來源。
- 數據卡與圖表需有清楚標題。
- 錯誤與資料狀態需能被文字閱讀。
- 對比度需足夠。
- 互動元件需具備可辨識焦點狀態。

### 14.3 前端禁止事項

- 不得自行補零。
- 不得自行補前值。
- 不得自行推導交易訊號。
- 不得自行改寫 ChatGPT 結論。
- 不得把關鍵位單獨轉成買賣訊號。
- 不得把夜盤交易流量標示成即時 OI。
- 不得把缺失資料顯示成正常資料。
- 不得因單一模組錯誤讓整個 Dashboard 空白。

## 16. 正式定案原則

1. Dashboard 是展示層，不是分析引擎。
2. Page Selection 是 V1.0 必要功能。
3. 五頁架構固定。
4. `summary` 為預設頁。
5. 所有頁面共用同一份 `dashboard_latest.json`。
6. Markdown 與 Dashboard JSON 必須同源。
7. 所有數據附來源、時間與狀態。
8. 缺失資料不得補 0。
9. 延遲、Fallback、估算資料必須標示。
10. 燈號必須附文字。
11. 選擇權近月與當週必須分開。
12. 日盤後法人 OI 與夜盤新增交易流量必須分開。
13. 選擇權關鍵位不可單獨作為交易訊號。
14. 單一錯誤不得拖垮整體 Dashboard。
15. 不完整時仍需顯示 Partial、錯誤、Fallback 與未完成項目。
16. Dashboard 必須反映 Markdown 報告模板的完成度與資料品質規則。
17. 只有實測驗收通過，才能宣稱 Dashboard 完成。
