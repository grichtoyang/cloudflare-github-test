# 每日盤前分析 V1.0｜專案總覽

- 文件名稱：`PROJECT_OVERVIEW.md`
- 版本：`V1.0`
- 狀態：`APPROVED`

## 1. 專案目的

建立一套可每日執行、可追溯、可驗證、具備錯誤隔離與 fallback 機制的「每日盤前分析」系統，於台股開盤前彙整市場資料，產出結構化 Markdown 分析報告與 Dashboard。

本系統的核心不是單純抓取資料，而是：

1. 自動取得資料
2. 保存原始資料
3. 正規化與驗證資料
4. 執行市場分析
5. 產出可追溯的分析報告
6. 在部分資料失敗時仍盡可能完成報告

## 3. 核心功能

### 3.1 資料取得

依照已定義的資料來源與資料介面，自動取得每日盤前所需資料。

### 3.2 原始資料保存

保留原始回傳內容與必要 metadata，包括：

- 資料來源
- 資料集名稱
- 取得時間
- 目標交易日期
- 回傳狀態
- 原始內容
- 錯誤訊息或備註

### 3.3 資料正規化

將不同來源的資料轉換為統一格式，處理：

- 欄位名稱
- 日期與時間
- 數值格式
- 單位
- 漲跌方向
- 商品、契約與到期月份
- 缺值與異常值

### 3.4 資料驗證

至少執行：

- 結構驗證
- 欄位驗證
- 日期驗證
- 數值驗證
- 邏輯驗證
- 跨來源一致性驗證

### 3.5 分析引擎

依據通過驗證或被明確標記為部分有效的資料，執行：

- 市場環境判讀
- 台股與台指期方向分析
- 期貨籌碼分析
- 選擇權支撐壓力分析
- 國際市場影響分析
- 事件與新聞影響分析
- 風險情境與交易注意事項

### 3.6 報告輸出

產出：

- Markdown 綜合分析報告
- 資料取得狀態
- 資料品質與完整度
- 主要結論
- 關鍵價位
- 多空情境
- 風險與失效條件
- 來源與追溯資訊

### 3.7 Dashboard

Dashboard 為核心功能，至少應能呈現：

- 台股與台指期主要資訊
- 選擇權籌碼
- Call Wall
- Put Wall
- Gamma Wall
- Gamma Flip
- Max Pain
- 重要支撐與壓力
- 資料更新時間
- 資料品質與異常狀態

## 4. 日期與時間規則

所有資料必須明確區分：

- 資料所屬交易日期
- 資料實際取得時間
- 市場所在地時區
- 盤前分析執行時間

不得因系統時間、UTC 轉換或跨日問題，誤用其他交易日資料。

## 5. 錯誤、Fallback 與持續執行原則

系統不得因單一資料來源、單一 endpoint 或單一分析模組失敗，就直接停止整體流程。

應遵守：

1. 記錄錯誤
2. 嘗試既定 fallback
3. 將受影響模組標記為失敗或部分成功
4. 繼續執行其他不受影響模組
5. 在仍可產出時，必須產出 Markdown 報告
6. 報告中明確揭露缺失、限制與未完成項目

## 6. 執行結果狀態

- `SUCCESS`：主要流程完整成功
- `PARTIAL_SUCCESS`：部分資料或模組失敗，但仍產出可用報告
- `FAILED_WITH_REPORT`：核心流程失敗，但仍產出錯誤與狀態報告
- `FAILED_NO_REPORT`：連最低限度報告都無法產出

不得將 `PARTIAL_SUCCESS` 或 `FAILED_WITH_REPORT` 誤標示為完整成功。

## 7. 設計原則

1. Data First：先取得與驗證資料，再進行分析
2. Traceability：每項重要結論均應可追溯至資料來源
3. Facts vs. Inference：事實、推論與預測必須分開
4. No False Completeness：資料缺失不得假裝完整
5. Risk-Control Priority：風險控管優先於方向預測
6. No OCR Core：OCR 不作為核心依賴
7. No Unauthorized Changes：未經確認不得任意更改既定規則
8. Failure Isolation：單一模組失敗不得無故拖垮全系統
9. Reproducibility：相同輸入應能產生可解釋、可重現的結果

## 8. 系統邊界

本 V1.0 不包含：

- 自動下單
- 自動交易執行
- 保證獲利或保證預測準確
- 以 OCR 作為核心資料來源
- 未經核准的資料來源或分析規則變更

## 9. 成功標準

本專案完成的必要條件包括：

- 能依規定流程取得資料
- 能保存與追溯原始資料
- 能辨識資料缺失與異常
- 能在部分失敗時繼續執行
- 能產出明確標示狀態的 Markdown 報告
- 能產出符合規格的 Dashboard
- 報告不得隱瞞錯誤、缺失或限制
